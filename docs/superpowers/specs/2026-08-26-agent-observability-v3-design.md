# Agent 评测与异常监控 v3 设计

## 目标

修正首页模块诊断的语义，避免把“多条 Trace 中出现问题的比例”误作模块质量指标；为首页合格产物和过程效率增加子指标折叠；新增独立的“异常监控”页面承载响应、流式、成本、Tool、一次执行和商业化/风控监控。

## 1. 模块诊断语义

模块诊断只表达节点级 Judge 状态和证据覆盖，不表达模块异常率。每个模块展示五态计数：`PASS`、`FAIL`、`DERIVED_FAIL`、`UNKNOWN`、`N/A`，并单列：

- 首错次数：该节点作为首个非派生失败的 Trace 数量；
- 派生失败次数：由上游首错传播到该节点的次数；
- Evidence 覆盖：有局部输入/输出/证据的节点数量与总节点数量。

节点卡片的主状态从“问题比例”改为最具代表性的 Judge 状态或状态分布，默认不显示百分比。点击节点仍然进入 Task / Trace，并带入节点与状态筛选。Root Cause 分布只统计首个非派生失败，派生失败不重复计数。Mock 数据的展示文案明确标注“节点状态计数 / Evidence 覆盖”，避免 100% 被误读为质量分数。

## 2. 首页子指标折叠

合格产物与过程效率 Section 各增加一个图标按钮，按钮带有 tooltip 和 `aria-expanded`。默认展开，用户收起后保留：Section 标题、总指标、趋势线、总指标口径和全部产物分母；子指标卡区域隐藏。展开/收起只影响当前页面会话，不改变筛选、下钻 URL 或聚合数据。按钮在移动端保持可点击并不挤压标题。

## 3. 独立异常监控页

新增第 8 个导航入口 `/anomaly-monitoring`，页面聚合共享性能 selector 的原始 Mock 数据。页面按四个分区组织：

### 响应与流式

- 总时延效率 = 平均实际 latency / 平均预期 latency；
- 四档效率带：`<=1.0` 正常、`1.0–1.5` 可接受、`1.5–2.0` 低效、`>2.0` 异常；
- TTFT：无埋点或基线时显示 `UNKNOWN / 基线未建立`；
- 模型吞吐量 = 总 token 吞吐量 / 模型总耗时。

### Token、缓存与成本

- Input Token Count、Output Token Count、总 Token；
- 输入/输出成本偏离率，按同类任务基准计算；基线不存在时显示 `UNKNOWN`；
- 缓存命中数量与命中率；
- 成本评测分母只包含成功/合格产物；失败产物仍展示原始 Token 与调用次数。

### 调用与一次执行

- Model Call、Tool Call、Retry、Loop 原始计数；
- 单个 Tool 调用频率 = 该 Tool 调用次数 / Tool 总调用次数，并同时展示失败次数；
- 一次执行成功率 = 首次成功执行 / 总执行次数；Retry/Recovery 成功不计入一次成功。

### 商业化与风控

- 风控拦截率 = 风控拦截 / 总 query 数；
- 风控拦截原因归一化分布；
- 商业化拦截率 = 商业化拦截 / 总 query 数；
- 商业化原因归一化分布，覆盖权益不足、配额耗尽、付费墙、能力未购买、超限等。

所有异常卡、原因项和异常数据点都可点击回到已有 Task / Trace 页面，携带监控维度、异常类型和全局筛选。现有“性能监控”保留 P50/P90/P95、Tool baseline、Model 明细等兼容分析，不与异常监控页重复为同一总分。

## 4. 响应式与验证

- 1440、1024、390 三种视口检查无页面级横向溢出；表格可在自身容器横向滚动。
- 折叠按钮、异常卡、原因分布和下钻按钮在窄屏可访问，中文标题和状态标签不被截断。
- 增加模块诊断计数语义、折叠状态、异常监控指标和全链路下钻测试。

## 非目标

本次不接入真实后端、Langfuse、数据库或线上成本基线；没有基线的数据继续使用 `UNKNOWN / 基线未建立`，不虚构通过或失败。
