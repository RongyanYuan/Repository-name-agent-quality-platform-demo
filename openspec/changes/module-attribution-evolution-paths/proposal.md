## Why

过程评分当前没有与每个归因和治理路径精确绑定，整条Trace或Skill级状态无法表达同一模块多归因、多路分流的差异。用户已确认方案并要求apply，需要在评分详情呈现每条路径的可进化、分流、准出与上线状态。

## What Changes

- 显式绑定当前Trace/评测包/自动版本/模块评分或细项到Finding、归因与独立进化轮次；不按同Case或Skill交叉猜关联。
- 模块表呈现简短进化摘要，二级详情列出各归因及其处理路径，每条路径有四阶段状态、时间和完整历史。
- 模块名及普通行直接进入该模块的进化方向，默认收起只显示归因短名称；点击后呈现状态与完整历史，含明确旧评测包。删除独立治理链路Tab，复核历史仍有独立入口，旧治理链接转向对应评测模块。
- Case / Trace 列表保留完整 Mock Case / Trace 范围，关闭详情后清除临时 Trace / Session 定位，避免列表被详情上下文缩窄；分页以更大的可读批次展示完整数据。
- Case / Trace 筛选增加精确时间窗口，以及按数据集类型和具体数据集名称筛选；结果严格使用 Trace 级数据集成员关系。
- 可进化判断读取PRD直接/聚类优化及已配置触发条件，低分只作候选线索；无门槛显示待配置。
- 精确关联数据集/实验/准出/发布，分开单能力与窗口准出、准出与实际上线，策略迭代未回传结果显示等待回传。
- 支持Skill固定源版本及记忆/Reason/Act等独立治理对象的筛选跳转，保持Skill互斥、旧链接和返回定位。
- 增量Mock覆盖同模块多归因、同归因多路、已准出未上线、回滚、新轮次及缺绑定边界；保留历史评分/复核/冻结报告。

## Capabilities

### New Capabilities

- `module-evolution-provenance`: 评分到归因与独立目标轮次的精确关系、历史与隔离。
- `four-stage-module-evolution`: 模块/细项二级详情的四阶段治理展示和规则口径。
- `governance-target-workbench-links`: Skill/非Skill目标与数据集、实验、历史的精确筛选和返回。

### Modified Capabilities

无主规格目录；沿用身份契约，根据用户最新指令将 Case 详情收敛为三个Tab，治理记录统一在评测模块中查看。

## Impact

React/TypeScript/Vite及本地Repository不变，主要影响模块选择器、过程矩阵/详情、Case导航和数据集工作台。四主页面保持；Case详情为Session对话、评测中心、产物评测三个Tab，PRD归因原文保持；无新阈值、真实服务、自动准出或实际发布。
