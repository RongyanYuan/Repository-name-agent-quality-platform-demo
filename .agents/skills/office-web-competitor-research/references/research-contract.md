# Research contract

## Decision
Which Office web jobs should Baidu prioritize, which interaction model should be default, and what advantage survives general-agent commoditization?

## Four axes
- Context: Office / non-Office / mixed. Classify by job and success criteria, not visual style or file extension.
- Input: attachment / one sentence / mixed.
- Guidance: blank / clarification / template / inspiration.
- Output: webpage / interactive tool / PPT / image. Word/Excel are sources and optional companion deliverables.

## Evidence types
- OBSERVED: directly executed, with screenshot/output and timestamp.
- OFFICIAL_CLAIM: first-party page/documentation, not tested.
- USER_EVIDENCE: interview/observed behavior, with participant and context.
- INFERENCE: reasoned interpretation and counterevidence.
- UNKNOWN: not verified.

## Control variables
Record product UI entry, platform, app/model version when visible, account tier, locale, region, date, task and material versions, prompt, attached files, template, time budget and repeat index. Never infer unavailable values.

## Scope and gates
Start with 6 domestic end-user products; screen access and capability, then shortlist 3–4 for full tasks. Add 2–3 global web specialists as capability references. Internal Baidu products are a baseline, not assumed differentiation.

Gate 1: reachable and correct product entry. Gate 2: task supported. Gate 3: first draft captured. Gate 4: acceptance or bounded failure. Gate 5: same-task synthesis. Publish no league table before comparable evidence exists.

## User mental-model research
UI analysis can suggest expectations but cannot establish user beliefs. Use task-based interviews: ask participants what output they would choose before naming web/PPT/image; show matched outputs in randomized order; ask when they would present, browse, print, edit, share or update. Record choice, rationale, task success and willingness to use in a real delivery. Include counterexamples: attractive Office work and accuracy-critical non-Office work.
