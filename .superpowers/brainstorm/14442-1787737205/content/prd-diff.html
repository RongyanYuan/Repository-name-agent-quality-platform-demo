A

在现有七页 IA 上做增量改造（推荐）

保留当前 Metric → Trace → Case → Dataset → Benchmark 导航，只替换主指标口径、Task/Trace 数据模型和性能/风控分区。风险最低，能最大化复用已经完成的交互闭环。

B

重构为“满意度漏斗 + 模块评测”双主导航

把用户满意度、有效产物、模块状态和线上监控提升到一级入口；Case/Dataset/Regression 作为治理工作区。产品叙事最贴合 PRD，但需要较大信息架构调整。

C

先做数据模型和评测配置，页面延后

优先落地五态 Eval、局部 Evidence、Root Cause Attribution、接受信号和指标公式；先不改视觉页面。长期最稳，但短期无法直观看到新 PRD 的产品变化。

PRD 中需要你确认的 5 个口径

  • 复杂度一期采用 Simple/Complex，还是保留 Medium 兼容展示？
  • 时延是“有效产物”的硬门槛，还是独立效率指标？
  • “文件有效性”是否替换当前“结果可用性”，还是两者同时保留？
  • TTFT、风控/商业化拦截是否纳入一期可视化？
  • Memory 暂无正式 KPI 时，是否只展示节点状态和 UNKNOWN/证据？
